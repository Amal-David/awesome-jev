# Projects submitted around the HN launch

Reviewed on September 22, 2026. [HN discussion](https://news.ycombinator.com/item?id=49802160) · [Selected projects](REVIEWED.md).

The first discussion snapshot contained 32 comments. Seven projects were shared there; two more arrived through GitHub. The decisions below are based on source inspection, not live testing. No submitted project was installed, no API credits were spent, and no accounts were created.

## Added

| Project | Why it made the list | What was checked |
|---|---|---|
| [nospace](https://github.com/riesvile/nospace) | A small, reusable typing library with a clear division between word-split selection and spelling correction. | [Provider code](https://github.com/riesvile/nospace/blob/main/src/server/providers.ts), [editor lifecycle tests](https://github.com/riesvile/nospace/blob/main/test/engine.test.ts), and the public demo page. Tests cover stale replies, caret preservation, composition input, and undo. Experimental English handling; hosted inference is required. [HN submission](https://news.ycombinator.com/item?id=49802812). |
| [wellposed](https://github.com/suraj-phanindra/wellposed) | Useful before making a Jev request: checks missing options, broken references, and question types without a model call. | [Structural linter](https://github.com/suraj-phanindra/wellposed/blob/main/skills/wellposed/scripts/structural.mjs), [tests](https://github.com/suraj-phanindra/wellposed/blob/main/skills/wellposed/eval/structural.test.mjs), and optional semantic checker. Heuristic, version-specific rules; the author's model-labeled evaluation is not independent validation. [HN submission](https://news.ycombinator.com/item?id=49803528). |
| [llm-typesafe](https://github.com/simonw/llm-typesafe) | Makes Jev usable through an existing CLI and Python library, including stdin, templates, and async calls. | [Client](https://github.com/simonw/llm-typesafe/blob/main/llm_typesafe.py) and [error tests](https://github.com/simonw/llm-typesafe/blob/main/tests/test_errors.py). Fixed HTTPS endpoint, redirect refusal, and malformed JSON handling. The host tool's normal logging still applies. Submitted by the author in [issue #2](https://github.com/Amal-David/awesome-jev/issues/2). |

These are source-reviewed additions, not claims that the upstream tests passed here. Their original licenses and longer notes remain in the catalog.

## README changes

The feedback singled out a sentence explaining why the list existed. That sentence and the opening slogan were unnecessary; both are gone. Project entries now have a short description on their own line, grouped by use. Refresh metadata and extended cautions are lower down. The existing X links, preview images, videos, attribution, and gallery renderer are unchanged.

The layout references were [Awesome Cursor Rules](https://github.com/PatrickJS/awesome-cursorrules), [Awesome](https://github.com/sindresorhus/awesome), [Awesome Selfhosted](https://github.com/awesome-selfhosted/awesome-selfhosted), [Awesome Node.js](https://github.com/sindresorhus/awesome-nodejs), and [Awesome Claude Code](https://github.com/hesreallyhim/awesome-claude-code). This was a sample of established lists, not a survey of the top 100. Only the listing pattern was borrowed; no project descriptions, sponsor blocks, or branding were copied.

Editorial pushes now rebuild offline. The scheduled four-hour discovery process remains separate, so a writing change does not also import unrelated projects. The README continues to list only selected entries; the broader discovery catalog is labeled separately.
